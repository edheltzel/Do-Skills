# Fetch plumbing: resolved-thread exclusion and bot-noise stripping

Copy-paste recipes for pulling PR comments cleanly before triage. Both are optional —
the basic `gh pr view` / `gh api` calls in SKILL.md work without them — but they cut
noise dramatically on bot-reviewed PRs (CodeRabbit, Copilot, Claude, etc.).

Set up context first:

```bash
gh pr view --json number,author --jq '{number, author: .author.login}'
gh repo view --json owner,name --jq '{owner: .owner.login, name: .name}'
gh api user --jq '.login'
```

Store as `$PR_NUMBER`, `$PR_AUTHOR`, `$OWNER`, `$REPO`, `$CURRENT_USER`.

## Exclude comments in resolved review threads

Comments whose thread is already resolved are usually `ignore` items. Fetch their IDs
up front and filter them out rather than triaging them:

```bash
RESOLVED_IDS=$(gh api graphql \
  -F owner="$OWNER" -F repo="$REPO" -F pr="$PR_NUMBER" \
  -f query='
    query($owner: String!, $repo: String!, $pr: Int!) {
      repository(owner: $owner, name: $repo) {
        pullRequest(number: $pr) {
          reviewThreads(first: 100) {
            nodes {
              isResolved
              comments(first: 100) { nodes { databaseId } }
            }
          }
        }
      }
    }
  ' \
  --jq '[.data.repository.pullRequest.reviewThreads.nodes[]
         | select(.isResolved)
         | .comments.nodes[].databaseId
         | select(. != null)]')
```

`first: 100` covers typical PRs; very large PRs (>100 threads or >100 comments in one
thread) would need pagination. Issue comments (summary/walkthrough posts) are not part
of review threads, so this only affects line-specific comments.

## Strip bot boilerplate before triage (`clean_body`)

Bot reviewers bury the actual finding under collapsible analysis chains, "Prompt for AI
Agents" blocks, committable suggestions, and footer tips. Strip that before classifying —
otherwise the noise labels get applied to the packaging instead of the point. Order
matters: `<details>` blocks must go before the `---` footer pattern, because bot analysis
chains contain `---` separators that would otherwise truncate the real finding.
Substantive `<details>` blocks (e.g. "Suggested fix") are preserved.

Write the filter to a temp file with a single-quoted heredoc (avoids shell escaping
issues), then apply it to both comment endpoints:

```bash
cat > /tmp/triage_comments.jq << 'JQEOF'
def clean_body:
  gsub("<!-- suggestion_start -->.*?<!-- suggestion_end -->"; ""; "s")
  | gsub("<!--.*?-->"; ""; "s")
  | gsub("<details>\\s*<summary>\\s*🧩 Analysis chain[\\s\\S]*?</details>"; ""; "s")
  | gsub("<details>\\s*<summary>\\s*🤖 Prompt for AI Agents[\\s\\S]*?</details>"; ""; "s")
  | gsub("<details>\\s*<summary>\\s*📝 Committable suggestion[\\s\\S]*?</details>"; ""; "s")
  | gsub("<details>\\s*<summary>Past reviewee.*?</details>"; ""; "s")
  | gsub("<details>\\s*<summary>Recent review details[\\s\\S]*?</details>"; ""; "s")
  | gsub("<details>\\s*<summary>\\s*Tips\\b.*?</details>"; ""; "s")
  | gsub("\\n?\\n---\\n+(?=\\s*(?:✨\\s*Finishing Touches|🪧\\s*Tips?|🤖\\s*Generated|<sub>|_Generated by|Generated by Claude|Generated with))[\\s\\S]*$"; ""; "s")
  | gsub("^\\s+|\\s+$"; "")
  | if length > 4000 then .[:4000] + "\n\n[comment truncated]" else . end
;
[(add // []) | .[] | select(
  .user.login != $pr_author and
  .user.login != $current_user and
  (.id as $comment_id | ($resolved_ids | index($comment_id) | not))
)] |
map({
  id,
  user: .user.login,
  path,
  line_display: (
    .line as $end | .start_line as $start |
    if $start and $start != $end then "\($start)-\($end)"
    else "\($end // .original_line)" end
  ),
  body: (.body | clean_body),
  created_at
})
JQEOF

# Line-specific review comments
gh api --paginate "repos/$OWNER/$REPO/pulls/$PR_NUMBER/comments" | \
  jq -s --arg pr_author "$PR_AUTHOR" --arg current_user "$CURRENT_USER" \
  --argjson resolved_ids "$RESOLVED_IDS" \
  -f /tmp/triage_comments.jq

# Summary/walkthrough issue comments: same filter, but drop the $resolved_ids
# condition and the path/line_display fields (issue comments have neither)
gh api --paginate "repos/$OWNER/$REPO/issues/$PR_NUMBER/comments" | \
  jq -s --arg pr_author "$PR_AUTHOR" --arg current_user "$CURRENT_USER" \
  --argjson resolved_ids '[]' \
  -f /tmp/triage_comments.jq
```

Notes:

- Excluding `$PR_AUTHOR` keeps your own replies out of the triage list; drop that
  condition if the user wants their own comments included.
- If triaging resolved threads is explicitly requested, set `RESOLVED_IDS='[]'`.
- Even after stripping, keep the `stale` check from SKILL.md: compare the comment's
  commit SHA against the current code at that line.
