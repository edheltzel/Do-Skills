# Frontend

Web frontend - Astro, CSS, React effects, design systems and their migration, tokens, component docs, landing pages, redesign audits, UI and code review, UX flows, and cleanup.

## Installation

Every skill in this group:

```bash
npx skills add https://github.com/edheltzel/Do-Skills/tree/master/skills/project/frontend
```

One skill by exact name:

```bash
npx skills add edheltzel/Do-Skills --skill=<skill-name>
```

## Skills

| Skill | Description |
|-------|-------------|
| [`do-astro`](./do-astro/) | Skill for building with the Astro web framework. |
| [`do-build-design-system`](./do-build-design-system/) | Use when someone wants a design system built from the UI an app already ships, or one phase of it, such as "extract tokens from the app", "add states to our Button", "replace the hardcoded colors with tokens" or "start a design system". |
| [`do-cleanup-web`](./do-cleanup-web/) | End-of-session cleanup pass for TypeScript, React, and web code. |
| [`do-component-docs`](./do-component-docs/) | Use to write one component's documentation entry from its code, stories and real call sites, such as "document the button", "write docs for Select", "what states does Toast have", or usage rules for a new or changed component. |
| [`do-design-system`](./do-design-system/) | Build accessible, themeable UI components, and when asked, capture the project's brand into DESIGN.md plus a live style-guide page. |
| [`do-design-system-boss`](./do-design-system-boss/) | Use for vague whole-app design system asks on an app that already ships UI, such as "our UI is a mess, fix it", "we need a design system", "we hardcode colors everywhere", "make the buttons consistent" or "check the app before I ship". |
| [`do-landing-page`](./do-landing-page/) | Build a landing page: one offer, one audience, one action, then the page that wins it. |
| [`do-migrate-design-system`](./do-migrate-design-system/) | Use when an app has to move onto a design system that already exists, such as "migrate the app to our design system", "move every screen onto the new components", a rollout, or an adoption audit. |
| [`do-modern-css`](./do-modern-css/) | Teaches agents to write modern CSS using native features instead of legacy hacks, workarounds, and JavaScript. |
| [`do-no-use-effect`](./do-no-use-effect/) | Prevent unnecessary React `useEffect` usage by steering code toward derived state, event handlers, memoization, `key`-based resets, `useSyncExternalStore`, and framework or query-library data APIs. |
| [`do-redesign`](./do-redesign/) | Audit an existing page or component for generic design, report every finding, then fix the approved ones in place. |
| [`do-review-frontend`](./do-review-frontend/) | Comprehensive React/TypeScript frontend code review with per-area review skills, run in parallel where the agent supports subagents and sequentially otherwise. |
| [`do-token-mapping`](./do-token-mapping/) | Use to report how hardcoded style values on a page, file or diff map onto a project's existing design tokens, such as "are we using our tokens here", "which hardcoded colors map to which tokens", a token audit or planning a token migration. |
| [`do-ui-review`](./do-ui-review/) | Use to critique a screen, flow, prototype or running build, accessibility included, and rank what is broken, such as "check this page before I ship", "is this flow ready", "is it accessible", keyboard or screen-reader checks, "it feels off on my phone" or "it feels janky". |
| [`do-ux-flow-plan`](./do-ux-flow-plan/) | Create UX-first plans as flow trees, then attach concrete function names, files, and implementation anchors after the high-level flow is clear. |
