# Workflow

Shipping and collaboration - commits, PR babysitting, review and triage, GitHub projects and stacks, safe PR workflow, worktrees, docs, and technical writing.

## Installation

Every skill in this group:

```bash
npx skills add https://github.com/edheltzel/Do-Skills/tree/master/skills/global/workflow -g
```

One skill by exact name:

```bash
npx skills add edheltzel/Do-Skills --skill=<skill-name>
```

## Skills

| Skill | Description |
|-------|-------------|
| [`do-commit`](./do-commit/) | Commit local changes as a Conventional Commit. |
| [`do-docs`](./do-docs/) | Author or improve one Diataxis page, or write one short learning when a verified fix's reasoning is not in the code, tests, or docs. |
| [`do-gh-pm`](./do-gh-pm/) | GitHub Projects management via gh CLI — creating projects, managing items/fields, plus opinionated PM recipes — board bootstrap, Epic→Feature→Task issue hierarchy with sub-issue linking, label policy, running a plan against the board, picking next work, and status reporting. |
| [`do-gh-stack`](./do-gh-stack/) | Manages stacked PRs and splits multi-part work into reviewable branches. |
| [`do-git-pr-babysit`](./do-git-pr-babysit/) | Monitor your pull request through CI and review until ready. |
| [`do-git-pr-comment`](./do-git-pr-comment/) | Draft and post attributed GitHub pull-request comments, inline review comments, and replies. |
| [`do-git-pr-modernize`](./do-git-pr-modernize/) | Reassess and update an old pull request against its current base. |
| [`do-git-pr-review`](./do-git-pr-review/) | Review a remote pull request by URL or number and draft actionable comments. |
| [`do-git-pr-review-triage`](./do-git-pr-review-triage/) | Triage pull-request review comments into accepted fixes and drafted replies. |
| [`do-git-pr-takeover`](./do-git-pr-takeover/) | Take over and finish an existing PR, branch, agent thread or do-handoff note while preserving contributor credit. |
| [`do-git-safe-pr-workflow`](./do-git-safe-pr-workflow/) | Safe GitHub pull request workflow for low-experience Git users. |
| [`do-git-worktree`](./do-git-worktree/) | Create, remove, list, and prune git worktrees under `.worktrees/<name>` in the main checkout. |
| [`do-readme-update`](./do-readme-update/) | Bring a repository's README back in line with the code. |
| [`do-tech-writing`](./do-tech-writing/) | Write clean, terse technical docs — commits, issues, PRDs, specs, and technical communication |
